# Garage — 5-minute demo script

This is the demo flow to walk the professor through. Rehearse it twice before
showing it for real.

> Prerequisites for the demo:
> - Backend running locally (`cd backend && npm run dev`)
> - iPhone on the same wifi as the Mac, app launched and signed-in to `demo@garage.app`
> - Mac firewall has `node` allowed (already done — see [README.md](./README.md))
> - LAN IP: `ipconfig getifaddr en0` matches what `flutter run --dart-define=API_BASE_URL=...` was started with

---

## The narrative

> "Garage is a smart car-companion app I built solo. It tracks fuel,
> maintenance, documents, and reminders for multiple cars — and it gets
> smarter the more you use it. The five things I want to show you are:
> a multi-car dashboard with predictive math, a real receipt-OCR via Gemini
> multimodal, AI-phrased reminder messages, and geofenced auto-logging."

---

## The flow

### 1. Home dashboard (0:00 – 0:30)

Open the app. The user is already signed in as `demo@garage.app`.

The home screen shows three banners stacked at the top — these are the live
reminder/expiry signals computed from the seeded data:

- 🚨 **Mécanique expires in 11 days** (red — critical)
- 🟠 **Oil change overdue, brake check in 1 day** (amber — soon)
- ⛽ **Predict-next fill-up: ~28 days remaining**

Talking points:
- *"The expiry banner is computed from a daily cron job and my own
  km-per-day calculation, not generic mileage intervals."*
- *"The predict card uses average tank capacity, my real consumption rate,
  and how often I drive."*

### 2. Multi-car switcher (0:30 – 0:45)

Tap the car-switcher chip in the AppBar. Three cars listed: **Range Rover
Sport** (primary), **Toyota Prius**, **Mercedes GLE**. Pick the Range Rover.

Talking points:
- *"All five features run per-car. Switching the active car re-keys every
  query in the app."*

### 3. Reminders → projection (0:45 – 1:30)

Tap the amber "Oil change overdue" banner. Lands on the reminders list.

For each reminder card, the AI message reads naturally — *"Your oil change
was due 240 km ago. At your current pace of ~42 km/day, you should book this
within the week."* — instead of a generic "due now."

Talking points:
- *"This message is generated by Gemini from the per-reminder math. It
  caches in the database and only re-runs when the underlying numbers shift
  more than 5% — that keeps cost down and avoids contradictions between the
  dashboard banner and the reminder list."*

### 4. Receipt OCR (1:30 – 2:30)

Back to home. Tap **Scan Receipt**. Take a photo of a real Lebanese
gas-pump receipt (or pick one from the library).

The screen shows "Reading receipt…" while Gemini multimodal extracts the
fields. It returns to a pre-populated form with:

- **Liters**, **price/liter**, **total cost** parsed correctly
- **Station** (e.g., `TOTAL Jounieh`)
- **Date** picked up from the receipt
- A **thumbnail of the receipt** at the top of the form
- Any low-confidence field is **highlighted in orange** with a "verify these"
  banner

Tap Save. The form returns to the fuel list with the new entry, station name
visible.

Talking points:
- *"Gemini multimodal does both the OCR and the field extraction in one
  call — no separate Vision API. The image gets preprocessed with sharp
  (greyscale, contrast, upscale to 1200px) before going to Gemini."*
- *"The processed image is hashed and cached, so re-scanning the same
  receipt is instant. The receipt URL is also persisted on the fuel entry,
  so you can always pull the original photo back up."*

### 5. Predict-next-fill-up explainer (2:30 – 3:15)

Go to the Fuel tab → tap the predict card.

A bottom sheet rises with a plain-English narration: *"Based on your last
6 months of fills, your Range Rover averages 9.2 L/100km. You drive about
42 km/day, so a full tank lasts roughly 22 days. You're about 28 days from
empty given your current odometer, last fill, and tank size of 85 L."*

Talking points:
- *"This explainer pulls from a separate Gemini endpoint with its own
  rate-limit (30 calls/day per user) so the dashboard load can never
  trigger LLM cost explosion."*
- *"If Gemini is down or rate-limited, it falls back to a deterministic
  template that interpolates the same numbers — the user always gets a
  message, just sometimes a less elegant one."*

### 6. Documents + auto-scheduled notifications (3:15 – 4:00)

Tap Documents tab on the Range Rover. Three docs:

- **Mécanique** (red — expires in 11 days)
- **Insurance**
- **Registration**

Tap mécanique → file opens in the system PDF viewer.

Talking points:
- *"Each document with an expiry date schedules two local notifications
  automatically — at -30 days and -7 days. iOS caps pending notifications
  at 64, so I implemented a global sweep that prioritizes the soonest 50
  across all cars and documents."*
- *"There's no FCM or APNs. Free Apple developer accounts can't sign apps
  with `UIBackgroundModes: fetch`, so all notifications are local."*

### 7. Geofenced auto-logging (4:00 – 4:45)

Open Settings (gear icon, top-right) → **Debug tools** → tap
**Simulate geofence entry**.

A local notification fires immediately: *"You arrived at TOTAL Beirut
Hazmieh — log a fill-up?"*. Tap it. The fuel form opens pre-filled with the
station name.

Talking points:
- *"This works whether the app is open or closed. The geofences are seeded
  from a backend `/gas-stations` endpoint that returns the nearest 10
  stations within 5 km."*
- *"In production this listens to `CLVisit` plus a 30-second dwell timer
  to filter out drive-by passes — `CLRegion` enter/exit alone is too noisy
  in dense urban areas."*

### 8. Architecture wrap-up (4:45 – 5:00)

> "Backend is plain Express + Prisma + Postgres on Neon — no Nest, no
> Docker required for dev. Frontend is Flutter with Riverpod, lean
> feature-first architecture. All five features have passing verify
> scripts plus widget tests. The README has the full stack — happy to
> drill into any part you want."

## What to do if something breaks live

| Symptom | Quick recovery |
|---|---|
| iPhone can't reach the backend | Re-check Mac firewall lets `node` in; or temp disable: `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate off` |
| OCR returns nothing | Set `DEMO_MODE=true` in `backend/.env` and restart `npm run dev`. Demo will use canned fields; story still holds. |
| App won't launch on iPhone | Re-sign: `cd mobile && flutter run --dart-define=API_BASE_URL=http://YOUR_IP:3000` (free certs expire every 7 days) |
| Reminder data looks weird | `cd backend && npx tsx prisma/seed.ts` (idempotent — just re-runs the seed) |
| Backend hangs on startup | Neon serverless cold-start can take ~5s on first request; just wait, don't kill it |

## Resetting between rehearsals

Re-seed wipes demo-account data and reinserts it freshly:

```bash
cd backend && npx tsx prisma/seed.ts
```

Optionally clear the OCR cache so the same receipt re-runs through Gemini
(otherwise it serves from cache and the demo looks suspiciously fast):

```sql
-- In Prisma Studio (npm run db:studio), table OcrCache → truncate.
-- Or via psql:
TRUNCATE "ocr_cache";
```

## What you should NOT click during the demo

- The logout button on the cars screen (kicks back to login — wastes time)
- The system Settings app from the iOS home screen (don't fumble out of the demo flow)
- Notifications that fire from random documents (will pull you out of context)
